## 1. Пользователи и профиль

### Регистрация

| Поле | Правило | Ограничение |
|---|---|---|
| `username` | Только буквы, цифры, `_`; начинается с буквы | 3–24 символа; паттерн `^[A-Za-z][A-Za-z0-9_]{2,23}$` |
| `email` | Валидный RFC-адрес | Макс. 320 символов; только разрешённые домены |
| `display_name` | Содержит ≥1 букву/цифру; допустимы пробел, `.`, `_`, `'`, `-` | 2–40 символов; паттерн `^(?=.*[\p{L}\p{N}])[\p{L}\p{N} ._'\-]{2,40}$` |
| `password` | Содержит ≥1 букву | 8–120 символов |
| `profession` | Опционально | Макс. 160 символов |

**Разрешённые домены для регистрации** — настраиваемый белый список (`APP_AUTH_REGISTRATION_ALLOWED_EMAIL_DOMAINS`).  
По умолчанию включает Gmail, Outlook, Yahoo, ProtonMail и ещё 20+ провайдеров.  
Проверяется также при смене email.

### Обновление профиля

- `display_name` и `profession` — те же правила, что при регистрации.
- `mail_enabled` (boolean) — включает/выключает вкладку почты для пользователя.

### Уникальность

В БД установлены `UNIQUE`-ограничения на:
- `app_users.username`
- `app_users.email`
- `app_users.display_name`

## 2. Аутентификация и безопасность

### JWT-токены

| Параметр | Значение по умолчанию | Переменная окружения |
|---|---|---|
| Access token TTL | 30 минут | `APP_JWT_ACCESS_TOKEN_TTL` |
| Refresh token TTL | 30 дней | `APP_JWT_REFRESH_TOKEN_TTL` |
| Secret | Base64, мин. 32 байта | `APP_JWT_SECRET` |

- Refresh token хранится в БД как хэш (`token_hash`), сам токен передаётся в HttpOnly cookie.
- Формат refresh token: `{tokenId}.{secret}` — ровно 2 сегмента через точку.
- Смена пароля инвалидирует **все** сессии пользователя кроме текущей.

### Rate limiting

- Настраивается через `AuthRateLimitPolicy`: ограничение на окно времени.
- Поддерживается Redis-бекенд для распределённого rate limiting (`APP_AUTH_RATE_LIMIT_REDIS_ENABLED`).

### Refresh cookie

| Атрибут | По умолчанию |
|---|---|
| Имя | `north_refresh_token` |
| Path | `/api/auth` |
| SameSite | `Lax` |
| Secure | `false` (включить для prod с HTTPS) |

## 3. Email и токены подтверждения

| Тип токена | TTL по умолчанию | Переменная окружения |
|---|---|---|
| Верификация email | 24 часа | `APP_AUTH_EMAIL_VERIFICATION_TOKEN_TTL` |
| Сброс пароля | 30 минут | `APP_AUTH_PASSWORD_RESET_TOKEN_TTL` |
| Смена email | 24 часа | `APP_AUTH_EMAIL_CHANGE_TOKEN_TTL` |

- Токены хранятся в БД как SHA-256 хэши (`token_hash`).
- После использования токен помечается (`used_at`), повторное использование невозможно.
- Новый email при смене хранится в `email_change_tokens.pending_email` до подтверждения.

## 4. Чаты

### Создание группового чата

| Поле | Правило |
|---|---|
| `title` | 2–120 символов, не пустое |
| `participants` | Макс. 50 username в одном запросе |
| `prejoin_history_policy` | `FULL_HISTORY` (по умолчанию) или `JOIN_ONLY` |

**`FULL_HISTORY`** — новый участник видит всю историю чата до своего вступления.  
**`JOIN_ONLY`** — новый участник видит только сообщения начиная с момента вступления.

### Личный чат (direct)

Личный чат — это всегда пара двух пользователей. Пара хранится как `(direct_user_low_id, direct_user_high_id)` — UUID-порядок, меньший UUID = low.

**Ограничения для личных чатов** — следующие операции запрещены:

| Запрещённое действие | Причина |
|---|---|
| Создать чат с самим собой | `ChatService` — явная проверка |
| Обновить название/настройки | Личные чаты не имеют названия |
| Добавить участников | Это уже не личный чат |
| Покинуть чат | Нет операции leave для direct |
| Забанить участника | Баны только в групповых чатах |
| Удалить чат как группу | Нет групповой операции |

### Групповой чат

- Только **владелец** (`owner_user_id`) может назначать/снимать модераторов.
- **Владелец не может покинуть группу** (сначала нужно передать права или удалить чат).
- Добавление участников — максимум 50 за один запрос.

### Участники (`chat_participants`)

- `left_at IS NULL` → активный участник.
- `left_at IS NOT NULL` → покинул чат (история доступа сохраняется).
- Уникальность: `(chat_id, user_id)` — нельзя добавить одного и того же пользователя дважды.

## 5. Сообщения

### Контент

| Поле | Ограничение |
|---|---|
| Текст сообщения | Макс. **65 535 символов** |
| `client_message_id` | 1–120 символов, не пустое; уникально в рамках `(chat_id, sender_id)` |
| Вложений на сообщение | Макс. **10** |

- `client_message_id` — idempotency key: повторная отправка с тем же ID не создаёт дубль.
- `server_order` — глобальный монотонно возрастающий идентификатор (identity sequence), уникальный.

### Шифрование

Контент сообщений шифруется **AES-256-GCM** на сервере:
- `content_algorithm` = `AES_256_GCM`
- `content_iv` = 12 байт (nonce)
- `content_ciphertext` = зашифрованный текст + 16-байтный GCM-тег
- `content_key_version` — ссылка на запись в `chat_message_keys`
- DEK (Data Encryption Key) хранится зашифрованным мастер-ключом провайдера (`LOCAL` или `AWS_KMS`)

### Удаление сообщений

| Условие | Разрешено |
|---|---|
| Пользователь удаляет своё сообщение | Всегда |
| Модератор/владелец удаляет чужое в группе | Да |
| Кто-либо удаляет чужое в личном чате | **Нет** — личные чаты не поддерживают удаление чужих сообщений |

Удаление для конкретного пользователя фиксируется в `user_deleted_messages` — другие участники продолжают видеть сообщение.

### Редактирование сообщений

- Редактировать может **только отправитель** своего сообщения.
- Время редактирования фиксируется в `edited_at`.

### Пересылка (forwarding)

- `forwarded_from_sender_id` и `forwarded_at` заполняются при пересылке.
- `user_pending_outgoing_messages.forwarded_from_message_id` — ссылка на оригинал в очереди.

### Пагинация

- По умолчанию 50 сообщений на страницу.
- Ссылки и вложения: 60 на страницу.

## 6. Вложения

| Параметр | Значение |
|---|---|
| Макс. размер файла | **25 МБ** (26 214 400 байт) по умолчанию; настраивается `APP_MEDIA_MESSAGE_ATTACHMENTS_MAX_SIZE_BYTES` |
| Макс. длина имени файла | 255 символов |
| Макс. длина mime-type | 255 символов |
| TTL для «осиротевших» вложений | 1 час (`APP_MEDIA_MESSAGE_ATTACHMENTS_ORPHAN_TTL`) |
| TTL presigned URL для скачивания | 10 минут (`APP_MEDIA_MESSAGE_ATTACHMENTS_MINIO_PRESIGNED_URL_TTL`) |

**Бизнес-правила вложений:**

- Нельзя прикрепить вложение другого пользователя.
- Нельзя привязать одно вложение к двум сообщениям.
- Вложение можно загрузить заранее (до отправки сообщения) — `message_id` будет `NULL` до отправки.
- Размер должен быть положительным (`size_bytes > 0` — CHECK в БД).

## 7. Реакции

- `reaction_key` — непустая строка (эмодзи или код).
- Один пользователь может поставить одну реакцию с одним ключом на одно сообщение — уникальность `(message_id, user_id, reaction_key)`.
- Повторный вызов на существующую реакцию — **toggle** (удаление).

## 8. Видеоконференции

| Поле | Правило |
|---|---|
| `title` | 2–120 символов, не пустое |
| `scheduled_at` | Обязательно, должно быть в будущем |
| `participants` | Макс. **50** за один запрос (create или add) |

- Конференция привязана к чату (`chat_id`) — запись появляется после создания конференции из чата.
- Статусы: `created → activated → started → ended` (через `activated_at`, `started_at`, `ended_at`).
- `video_conference_attendance` хранит **фактическое** присутствие (не приглашения).
- Одна запись `conference_recordings` на конференцию (1:1).
- Invite-ссылка типа `CONFERENCE` привязана к конференции по `target_id`.

## 9. Push-уведомления

| Поле | Ограничение |
|---|---|
| `endpoint` | Макс. 2048 символов, не пустой, уникальный |
| `p256dh` | Макс. 512 символов (Base64url-кодированный публичный ключ P-256) |
| `auth` | Макс. 256 символов (Base64url-кодированный auth secret) |

- VAPID публичный ключ должен быть несжатой точкой P-256: 65 байт, первый байт `0x04`.
- TTL push-сообщения: 1 минута по умолчанию (`APP_PUSH_TTL`).
- Таймаут HTTP-запроса к push-сервису: 5 секунд (`APP_PUSH_REQUEST_TIMEOUT`).

## 10. Ограничения БД (CHECK-constraints)

| Таблица | Ограничение | Описание |
|---|---|---|
| `chat_rooms` | `chk_chat_rooms_direct_pair` | Если `is_direct=true`, оба `direct_user_*_id` обязательны и различны; если `false` — оба NULL |
| `chat_rooms` | `chk_chat_rooms_prejoin_history_policy` | Только `JOIN_ONLY` или `FULL_HISTORY` |
| `chat_rooms` | `uk_chat_rooms_direct_pair` | Уникальная пара `(direct_user_low_id, direct_user_high_id)` — один личный чат между двумя пользователями |
| `message_receipts` | `chk_message_receipts_read_requires_delivery` | `read_at IS NOT NULL` требует `delivered_at IS NOT NULL` |
| `user_contacts` | `chk_user_contacts_not_self` | `user_id <> contact_user_id` — нельзя добавить себя |
| `invite_links` | `chk_invite_links_target_type` | Только `GROUP` или `CONFERENCE` |
| `message_dispatch_outbox` | `chk_message_dispatch_outbox_mode` | Только `FULL` или `ACK_ONLY` |
| `user_pending_outgoing_messages` | `chk_user_pending_outgoing_messages_status` | Только `SENDING` или `FAILED` |
| `chat_attachments` | `chk_chat_attachments_size_positive` | `size_bytes > 0` |

### Поиск
